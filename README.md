# 핀테크 코호트 리텐션 & 이행 퍼널 분석 (SQL 기반)

결제/이커머스 로그 데이터에서 **유저 리텐션**과 **이행 퍼널**을 SQL로 직접 산출한 프로젝트입니다.
"한 번 온 유저가 다시 오는가", "주문이 어느 단계에서 새는가"를 지표로 만들어 서비스 개선 액션까지 연결합니다.

- **데이터**: [Olist Brazilian E-Commerce](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce) (약 10만 주문, 실거래 로그)
- **기술**: SQL(SQLite), Python(pandas, matplotlib)
- **결과물**: 월별 코호트 리텐션 히트맵 · 재구매율 · 주문 이행 퍼널
- **노트북**: [`fintech_cohort_funnel.ipynb`](./fintech_cohort_funnel.ipynb) (Google Colab에서 바로 실행)

---

## 왜 이 분석인가

결제/금융 서비스에서 가장 중요한 두 축은 **리텐션(다시 오는가)** 과 **퍼널(어디서 이탈하는가)** 입니다.
매출은 신규 획득과 기존 유지의 합인데, 둘의 비중을 모르면 마케팅 리소스를 어디에 써야 할지 판단할 수 없습니다.
이 프로젝트는 로그 데이터에서 두 지표를 SQL로 산출하는 과정을 그대로 보여줍니다.

## 분석 설계

### 1. 월별 코호트 리텐션
각 고객의 **첫 구매 월**을 코호트로 잡고, 이후 N개월에 재구매한 비율을 산출합니다.
`WITH`(CTE) → 첫구매월/활동월 집계 → 개월차 계산 → `COUNT(DISTINCT)` 순으로 구성했습니다.

> **데이터 함정 처리**: Olist의 `customer_id`는 주문당 1개씩 새로 부여되고, 동일 인물을 식별하는 키는 `customer_unique_id`입니다.
> 리텐션을 `customer_id`로 잡으면 모든 고객이 1회성으로 집계돼 결과가 완전히 틀립니다.
> 이 분석은 전 구간에서 `customer_unique_id`를 사용하고, 취소 주문(`canceled`)은 유효 거래에서 제외했습니다.

### 2. 재구매율(Repeat Rate)
유효 주문 2건 이상 고객의 비율을 산출해, 비즈니스가 신규 획득에 의존하는 구조인지 진단합니다.

### 3. 주문 이행 퍼널(Fulfillment Funnel)
Olist에는 조회·장바구니 로그가 없지만, 주문의 단계별 타임스탬프(승인·발송·배송완료)로 이행 퍼널을 구성해
`구매 → 승인 → 발송 → 배송완료` 단계별 도달률과 이탈 구간을 계산합니다.

## 핵심 발견

- **고객 식별**: 주문 99,441건은 실제 96,096명이 낸 것. `customer_id`(주문당 1개)로 세면 전원 1회성으로 잡히는 함정을 `customer_unique_id`로 교정.
- **리텐션 구조**: 재구매율 **3.06%** (95,560명 중 2,924명). 월별 코호트 리텐션은 M0 100% → **M1 약 0.4~0.7%** 로 급락 → 기존 고객 재구매가 아니라 **신규 획득에 거의 전적으로 의존**하는 구조. CRM/리텐션이 미개발 레버임을 시사.
- **퍼널 진단**: 구매 100% → 승인 99.8% → 발송 98.2% → 배송완료 **97.0%**. 이행 자체는 매우 건강하며, 최대 이탈은 승인→발송 구간(약 1.6%p). 즉 성장 병목은 배송이 아니라 리텐션에 있음을 뒷받침.
- **모니터링 지표화**: 쿼리를 주기 스케줄링하면 코호트 리텐션·이행 퍼널을 지속 추적하는 지표 대시보드로 확장 가능.

## 실행 방법

1. `fintech_cohort_funnel.ipynb`를 Google Colab에서 엽니다.
2. 첫 셀에서 `kaggle.json`을 업로드해 Kaggle 인증합니다. (Kaggle → Account → Create New API Token)
3. 위에서부터 순서대로 실행하면 데이터 다운로드 → SQLite 적재 → 리텐션/퍼널 산출 → 시각화까지 자동으로 진행됩니다.
